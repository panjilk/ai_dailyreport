# AI 日报编辑规范

本文件是给 Codex 的编辑标准。目标：把机器采集的原始新闻，编成一份**可以直接口播的人工级稿件**。

## 一、选题标准

**只收大模型（foundation model）相关新闻**：

✅ 收录：
- 模型发布 / 版本更新 / 能力升级（GPT、Claude、Gemini、Qwen、GLM、DeepSeek、LongCat、MiMo 等）
- 模型开放权重、API 价格变化、上下文长度、推理速度等能力参数
- 厂商官方的模型相关工具（如语音、插件、Agent 框架）
- **大模型相关的论文/研究**（训练方法、量化、评测基准、对齐、安全）—— 这类**要保留**
- 权威机构的模型评测 / 安全报告
- 大模型的事故 / 安全问题（如某模型的代理泄露数据）

❌ 剔除：
- 与模型无关的行业新闻（流媒体推荐算法、游戏、硬件外设、海底电缆、投融资）
- 与大模型无关的论文（社会语言学语料库、纯机器人硬件、纯图形学）
- 个人博客的工具版本号更新（如 "llm 0.36 发布"）
- 无法核实事件日期的消息

**条数**：目标 6-8 条。

> ⚠️ **硬性：编辑后不得少于 5 条**。项目在少于 5 条时会**拒绝生成视频**。
> 采到的候选本来就少（通常 6-8 条），**判不准就保留**：
> 只要和大模型沾边（模型、论文、评测、事故、厂商动作）就留着，宁可多留不可错杀。
> 只剔除**明确无关**的（游戏、硬件、流媒体、非 AI 论文）。

## 二、口播稿（video_bullets）—— 最重要

这是视频里念出来的话，必须满足：

1. **长度 40-70 个汉字**，一到两句
2. **必须有主语**：谁做了什么。禁止"我们提出""这些结果表明""该研究"这类无主语表述
3. **必须有关键信息**：数字、版本号、能力指标、时间
4. **保留限定语**：原文是"厂商称/官方称"的，必须保留，不得写成既定事实
5. **不出现来源名**（IT之家、量子位、OpenAI News 等）、网址、括号标注、英文原文
6. **不出现「据…报道」「据…消息」「来源」这类转载句式**（❌「据报道，OpenAI…」）。渲染器会用
   `re.search(r'https?://|来源|据.{0,20}(?:报道|消息)', video_narration)` 检查，命中就**拒绝出片**。
   把信息来源删掉，直接陈述事实即可
7. **念出来要通顺**：避免长定语堆叠，避免书面语

### ⚠️ 硬性技术限制（违反会导致该条被**整条剔除**）

渲染器要把每条新闻的 `bullets` 截取成屏幕上的一行「核心事实」。规则：

- 每个 `bullets` 条目**必须包含标点**（`，` `。` `；`）；纯文字长句无法切分会被丢弃。
- 以**第一个逗号/分号**切出的片段**不得超过 76 字**。超了就重写：拆成两句，或把长定语提前。
- 建议每个 `bullets` 条目控制在 **40–76 字**。

**反例**（107 字无标点 → 整条被剔除）：
> ❌ 谷歌发布Gemini 3.8 Flash和Flash Lite两款语音模型 新模型有超过两千种声音还能用三十秒音频创建定制声音

**正例**（有标点、首段 45 字）：
> ✅ 谷歌发布 Gemini 3.8 Flash 与 Flash Lite 两款语音模型。新模型提供超过两千种声音，还能用三十秒音频创建定制声音。

### ⚠️ 机翻残留必须清除

部分条目的 `bullets` 由英文博客机翻而来，会出现**英文残留、缺标点、语序错乱**：

> ❌ 工具： Gemini 3.8 TTS Playground Google今天发布了两款新的Gemini文字转语音模型- gemini-3.8
> ❌ 你的浏览器不支持音频插件。

处理办法：
1. 先用 `source_text` / `abstract` / `narration` 里的信息，**重写成通顺中文**（含标点、首段 ≤76 字）。
2. 若该 bullet 是网页噪音（"你的浏览器不支持…"、导航文字、广告），**直接删掉**。
3. 重写后仍无法满足长度/标点要求 → **整条剔除**，宁缺毋滥。

### 好例子

> 智谱发布 GLM 五点三 Flash，能同时理解文字、图片和视频。它以较少的激活参数降低推理开销，模型权重也已开放下载。

> 研究团队提出 DeltaWAM 世界动作模型，在 RoboTwin 测试中，干净设置下平均成功率从 81.3% 提升至 85.4%。

> Ringg 的 AI 代理借助 GPT-5.6，为语音、聊天、WhatsApp 和网页提供多语言支持，厂商称已解决高达 65% 的客户来电，成本降低 90%。

### 坏例子（禁止）

> ❌ 我们进一步推出了 Multi-event Insight Network Dimensions（MIND）
> ❌ 这些研究结果表明，单凭记忆机制不足以完成这项复合任务
> ❌ 修剪大型预训练的基于变压器的 ASR 模型

## 二之二、nav_label（导航标签）—— 必须统一

`nav_label` 是视频画面上的短标签，代表**这条新闻的主体**。

### 规则

1. **必须是模型/技术的所属厂商**，即「这是**哪家**的东西」——**不是新闻里的使用方，也不是来源站**。用公司名：`OpenAI`、`Anthropic`、`Google`、`智谱`、`小米`、`腾讯`、`美团`、`MiniMax`、`DeepSeek`、`Liquid AI`。
2. **同一厂商，全期必须用同一个标签**。绝对禁止同一家公司出现两种标签。
3. **禁止**用以下内容当标签：
   - ❌ 来源站名：`Hugging Face`、`IT之家`、`量子位`、`OpenAI News`、`TechCrunch`
   - ❌ 模型系列名代替厂商：**GPT 一律写成 `OpenAI`**，`Hunyuan`→`腾讯`，`GLM`→`智谱`，`LongCat`→`美团`
   - ❌ **使用方**：新闻说「爱彼迎用 GPT-6」，标签仍是 `OpenAI`，不是 `爱彼迎`
   - ❌ 论文标题片段、`多模型对比`、`产品应用` 这类非厂商描述
4. **禁止使用 `研究团队`、`研究人员`、`作者`、`某团队` 这类空标签** —— 用户明确要求「必须具体到某个团队名字」。论文类新闻一律查出**作者单位**：

   - 先看 `abstract` / `source_text` 里的单位线索（例：摘要写「We introduce **Kaggle** Game Arena」→ 标签 `Kaggle`）
   - 抓不到就**取论文页**：`arxiv.org/abs/<id>` 只有作者名，**单位在** `arxiv.org/html/<id>v1` 或 `arxiv.org/pdf/<id>` 的**首页作者块**（找 `Affiliation:`）
   - 多个单位时取**第一作者或通讯作者**的单位；作者分散时取**出现次数最多**的单位
   - 真的查不到单位，才退回用**方法/模型名**（如 `World Action Agent`），**仍然不许写 `研究团队`**

   标题同样要具体：❌「研究团队提出 G²PTQ」→ ✅「中兴通讯提出 G²PTQ」。

### 对照表（照这个来）

| 新闻内容 | 正确 nav_label | 错误写法 |
|---|---|---|
| OpenAI 发布 GPT-6 Sol / Luna | `OpenAI` | ~~GPT~~ |
| 爱彼迎扩大使用 GPT-6 Astra | `OpenAI` | ~~GPT~~、~~爱彼迎~~ |
| Whisper 语音模型剪枝论文 | `OpenAI`（Whisper 是 OpenAI 的模型）| ~~Whisper~~、~~研究团队~~ |
| 谷歌发布 Gemini 3.8 语音模型 | `Google` | ~~Gemini~~ |
| 混元 A13B 开源 | `腾讯` | ~~Hunyuan~~ |
| 智谱 GLM-5.3-Flash | `智谱` | ~~GLM-5.3-Flash~~ |
| 美团 LongCat-2.5 | `美团` | ~~LongCat-2.5~~ |

**一句话**：标签回答「这是**哪家厂商**的东西」。



## 三、输出格式

写成一个 JSON 文件，顶层结构与输入一致，`stories` 数组每条包含：

```json
{
  "title": "标题（简洁，20-30 字，含主体动作）",
  "nav_label": "导航短标签（2-6 字）—— 必须是【新闻主体】，见第二节之二",
  "category": "模型发布 | 产品应用 | 技术洞察",
  "published": "YYYY-MM-DD",
  "event_date": "YYYY-MM-DD",
  "event_date_evidence": "事件日期的依据（原文摘录）",
  "source_name": "来源名",
  "source_url": "原文链接",
  "bullets": ["事实要点1", "事实要点2", "事实要点3"],
  "video_bullets": ["口播短稿（符合第二节要求）"],
  "verification": "official_announcement | official_changelog | company_post_and_report | extractive",
  "source_text": "原文关键摘录"
}
```

顶层字段：`date`、`title`、`edition_start_date`、`edition_note`、`stories`。

## 四、硬性约束

- **不得编造**数字、结论、日期。信息只能来自输入文件。
- 输入里信息不足的条目，宁可**剔除**，不要脑补。
- **保留原始 `source_url`**，不得改动。
- 输出必须是**合法 JSON**（UTF-8，无注释、无尾逗号）。
